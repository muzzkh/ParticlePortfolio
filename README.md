# Particle Portfolio

The deploy repo for **Muzzamil Khan**'s site,
[www.muzzamilkhan.com](https://www.muzzamilkhan.com): an interactive résumé
built with three.js. Visitors walk a procedurally generated desert and read
each chapter of the résumé from the waystones (glowing monoliths) along the
road. The desert itself is developed in
[muzzkh/arrakis](https://github.com/muzzkh/arrakis) and vendored here; see
[Updating the desert](#updating-the-desert).

Content is edited at [www.muzzamilkhan.com/management](https://www.muzzamilkhan.com/management)
(see [Updating the content](#updating-the-content)).

Browsers without WebGL get the intro screen with the PDF and contact links.
The site opens no connections beyond its own files and Google Fonts, and the
font stylesheet never holds up the page: where it is slow or blocked, the intro
appears after at most two seconds with system fonts.

## Run it locally

```bash
npm install
npm run dev
```

Then open the URL Vite prints (default `http://localhost:5173`).

To build for production:

```bash
npm run build
npm run preview
```

## Project structure

```
index.html                 # The site (generated by scripts/sync-desert.sh)
management/index.html      # The editor at /management (generated too)
public/
  Muzzamil_Khan_Resume.pdf # Linked from the intro screen and the résumé index
  media/, models/          # Images and 3D models added at /management
  waystone.svg             # Favicon (synced from arrakis)
  boot.js                  # Start-up helpers (synced from arrakis)
scripts/
  sync-desert.sh           # Pulls the desert in from a muzzkh/arrakis checkout
src/
  data/
    site.json              # All of the content
    schema.ts              # Its shape, for editing it by hand
  desert/                  # Vendored from muzzkh/arrakis, don't edit here
    main.js                # Scene, game loop, résumé orchestration
    waystones.js           # The monoliths and project landing pads, and their layout
    editmode.js            # Placement mode, for /management
    manage/                # /management itself
    resume/content.js      # Points at src/data/site.json and this repo (kept across syncs)
    games/                 # The Worm Pit, Thopter Ride and Sand Race, played in the desert
    minimap.js             # The minimap and the full map
    life/                  # Other walkers, wildlife, spice and passing events
    …                      # terrain, sandworm, walker, ornithopter, atomics, audio
```

## Updating the content

Use **/management** on the live site. Everything is there: waystones
(experience, education, skills) and projects with their highlights, formatted
details with images, cover images, links and 3D models (`.glb`); the profile,
intro text, contact links and résumé PDF; and a placement mode where you drag
stones, pads and the three games around the desert yourself (games can also be
hidden). Projects take a category and one of several built-in models, and
World → Life sets how many other walkers there are and whether there is
wildlife, spice and passing events. **Publish** makes one commit to
`main` here (`src/data/site.json` plus any added files under `public/`), and the
deploy workflow puts it live in a minute or two. Unpublished work is kept in the
browser until then.

### Signing in

The first time on a device, /management asks for a GitHub token and a
password. Make the token at GitHub → Settings → Developer settings →
[Fine-grained tokens](https://github.com/settings/personal-access-tokens/new):

- **Repository access:** Only select repositories → `muzzkh/ParticlePortfolio`
- **Permissions:** Repository permissions → **Contents: Read and write**

The token stays in that browser, encrypted with your password; after that, the
password is all you type. Anyone can open the page, but without a token it can't
change anything, and no secret ships with the site. It locks after 30 minutes
idle. On a new device, or when the token expires, make a new one.

You can still edit `src/data/site.json` by hand (types in
`src/data/schema.ts`). To replace the PDF by hand, overwrite
`public/Muzzamil_Khan_Resume.pdf`.

## Updating the desert

The desert's source of truth is [muzzkh/arrakis](https://github.com/muzzkh/arrakis).
Make changes there, then pull them in from a checkout next to this one:

```bash
scripts/sync-desert.sh ../arrakis
```

The script replaces `src/desert/`, the root `index.html` and
`management/index.html` (and copies the favicon), but keeps
`src/desert/resume/content.js`, which points the desert at `src/data/site.json`
and tells /management to publish to this repository.

## Deploying

Pushing to `main` (including a publish from /management) runs
`.github/workflows/deploy.yml`, which builds the site into `dist/` and publishes
it to the `gh-pages` branch with the `CNAME` for www.muzzamilkhan.com.

The previous React particle résumé was removed in favour of the desert; it is
in the git history (last present at `d2f56bd`).
